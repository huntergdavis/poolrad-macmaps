# 0.22.0 — How close they are to training

- Character details now show the **experience the game has recorded** and, for
  each class a character holds, **the next-level figure the game itself compares
  against**: either how much more is needed, or that the figure has been reached.
- A multiclass character gets a line per class. A class the game defines no
  further level for says so, and never counts as ready.
- Reaching a figure is **not** a level-up. The original game still needs a visit
  to a training hall, that hall must teach the class, and it charges its own fee
  — the pane says so. Nothing here trains, levels, edits experience or predicts
  what training would give.

Read from the same fields and the same comparison the game's own training hall
makes, and from the game's own threshold table rather than modern rules.

[Download the public APK](https://github.com/huntergdavis/poolrad-macmaps/releases/download/v0.22.0/poolrad-macmaps-0.22.0.apk)
and install over the existing app. **Bring your own ROM, Mac system and game**;
none are included. No game rules, stats or save formats change, and nothing is
written to guest memory.

Mac II universal, Android 5.0+, ARM64/ARMv7/x86/x86_64, versionCode 88.
Same prototype signing key; source tag `v0.22.0`.

**381 Java tests** and the rebuilt native party-probe suite pass, as does the
public APK asset gate. Private captures decode the whole sample party and agree
with the game's own character sheet. Verified live: where the game printed
`EXP: 2134` and `Level: 1` for a Fighter, the companion read
`Experience: 2134` and `Fighter level 1 · 2001 reached, ready to train`.

Nobody was trained through a hall to watch a level actually change, and the
hall's class restriction and fee are not modelled.
