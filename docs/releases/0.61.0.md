# 0.61.0 — Save states carry their notebook

**Loading a save now opens the notebook it was made with.** If you keep a
separate notebook per campaign, each save state remembers which one it belongs
with, so restoring a machine also brings back the right campaign's notes and
journal.

**How it works:** a save stores only a reference to its notebook — the
notebook's id, a few dozen bytes — not a copy of the notes. Your notes stay
where they are, in the notebook store, and are never duplicated into a save.

**What this means for you:**

- Make a save while a campaign's notebook is open, and loading that save later
  reopens that notebook, even if you had switched to another one in between.
- A save whose notebook you have since deleted still loads; it just keeps
  whatever notebook is open rather than failing.
- Deleting a save also removes its little notebook reference.

**Verified:** 603 Java tests, the native build, the APK ABI check, and a live
run with two notebooks — a save made under one was restored while the other was
active, and the active notebook switched back to the paired one.
