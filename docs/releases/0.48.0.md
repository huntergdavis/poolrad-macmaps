# 0.48.0 — Two real bugs in loading, found by running it

A patch on 0.47.0. Neither of these would have been found by reading the code.

- **The Finder step pressed Return.** Return in the Finder *renames* the
  selected item; it does not open it. So the sequence renamed "Adventurer's
  Journal Part 1" and opened that instead of the game. Typing to select and
  typing a line are now separate things, and the Finder never gets a Return.
- **`Cmd-L` was sent too early.** The probe sees the game's globals well before
  it is drawing menus and ready to be asked for one, so the key went nowhere and
  the sequence waited out its patience for a dialog nobody had opened. It now
  leaves the game alone for six seconds after it appears.

**Also fixed, from 0.47.0:** the Saved games dialog showed a summary and hid
every action behind it — an `AlertDialog`'s message and its item list occupy the
same space. And the Load action was never added at all. Both were found by
trying to photograph the feature.

## What this does not claim

**The load sequence has still not completed end to end on a live machine.** The
quit works, the Finder type-select picks the right application, and the game
comes back. Whether the load dialog then opens is unconfirmed, and it is tracked
as F86 rather than assumed.

A failure is safe: the sequence stops, says why, and leaves the guest alone.
Nothing is typed once a party is seen.

**Verified:** 532 Java tests, six native probe suites, 25 render checks, the APK
check. The two fixes above each have a test named for the failure they prevent.
