# 0.59.0 — Save states: real save/load, no restart

**The approach that replaces the withdrawn Load: whole-machine save states,
driven from the companion, that never touch the game's menus and never restart
the guest.** This is the P0 line the owner named — fast save/load done a
different way from the game's own disk grind.

**What's new, on the PoolRad menu:**

- **Quick save** — snapshot the entire running machine to a single quick slot.
- **Quick load** — put that machine back, in place, in a moment. No restart, so
  it cannot strand the emulator the way the old Load did.
- **Save states…** — give a snapshot a name, pick one to load, or delete old
  ones.

**How it works.** A save captures all of emulated RAM, the 68k CPU, and every
device's timing and interrupt state at a controlled boundary, plus the Mac II's
separate video buffer so the screen comes back exactly as it was — even on a
still screen the game was not already redrawing. The capture happens off the
emulation thread, and the file is a gzip of the machine image (~1.3 MB), written
atomically so a listing never shows a half-written save. Loading is the mirror:
read and decompress off-thread, then swap the machine back at the next safe
boundary.

**Verified live** on the running game: Quick save wrote a valid file; after
walking the state forward, Quick load snapped it back — both the underlying
game state and the visible screen — with the machine still running and
responsive.

**What is untouched:** backing up and restoring the game's own saved games under
**PoolRad → Saved games** still works and is unrelated to this.

**Verified:** 595 Java tests, the native build, and the APK ABI check.

[Download the public APK](https://github.com/huntergdavis/poolrad-macmaps/releases/download/v0.59.0/poolrad-macmaps-0.59.0.apk)
and install over the existing app. **Bring your own ROM, Mac system and game**;
none are included.
