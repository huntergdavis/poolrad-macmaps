# 0.54.0 — Where you found something

An open box appears on every square where the game said the party found
treasure.

**Open rather than closed**, because the mark means the thing has been taken —
not that there is something still to get. A different silhouette from the
ambush mark, so the two read apart at a glance: a struck-through creature is
where the trouble was, an open box is where the reward was.

## Why it only marks treasure

The trigger is one exact sentence out of the game's own strings — *"The party
has found Treasure!"* — which is what makes acting on it safe. There is no
phrasing to guess at and no pattern that might catch something else.

Deliberately narrow. **Look** and **Search** produce plenty of prose, and a map
covered in marks for every barrel examined would be worth less than one with a
handful that mean something.

Unlike a fight, a find happens while your position is perfectly readable, so the
square is simply the one you are standing on.

## Your existing maps are safe

The stored format goes to version 3. Version 1 and version 2 records still load
and read as "none of those remembered here" — the truth about them rather than a
loss.

The compatibility test now **builds** old records outright instead of trimming
bytes off a current one. It had already broken once on the previous bump;
building them means the next version will not quietly break it again.

**Verified:** 573 Java tests, six native probe suites, 58 render checks across
four suites, the APK check. The new render check holds a find and a fight to
being different marks, both true of one square at once, and neither erasing the
other.
