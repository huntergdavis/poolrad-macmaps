# 0.41.0 — Reading the machine at the speed it is moving

The companion used to read four regions of guest RAM four times a second for as
long as the map was open, whether or not the game was doing anything. Most of a
session is not doing anything: the game sits on a message, a menu or a prompt
and the party has not moved for a minute.

The rate now follows the guest's own screen.

| The screen has been still for | Reads every |
| --- | --- |
| under 2 seconds | 250 ms, as before |
| 2 to 15 seconds | 1 second |
| over 15 seconds | 3 seconds |

**Any movement puts it straight back to full rate**, and cancels a slow read
already scheduled — otherwise stepping through a door after a quiet minute
would take three seconds to reach the map.

It backs off rather than stopping, deliberately. A stopped poll needs something
to start it again, and being wrong about what that is means a companion that
has quietly stopped telling the truth. A slow poll that is wrong about being
idle is merely late.

**The other half of this needed no work.** Backgrounding the app already paused
the emulator, and foregrounding already resumed it.

**Verified:** 481 Java tests including eight new ones, five native probe suites,
25 render checks. Not verified here: battery life, e-ink, stylus or on-device
acceptance, which remain the owner's own — the effect of this one is best judged
over a long session on the tablet itself.

and install over the existing app. **Bring your own ROM, Mac system and game**;
