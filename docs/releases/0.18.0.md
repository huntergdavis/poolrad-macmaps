# 0.18.0 — Which spells are actually ready

- Tap a character: their details now say which memorized spells the original
  game will let them cast **right now**, and which ones they chose that still
  need rest, counted per spell level.
- A rest reminder appears only when something is genuinely waiting:
  *Resting in the original game would finish memorizing these.*
- A character with none reads *No spells ready to cast*, which is deliberately
  different from *Spell readiness unavailable*.
- No mana gauge — Pool of Radiance has none — and this app never memorizes,
  casts, rests or restores anything. It reports what the game already recorded.

Read from each character's own 21-slot memorized-spell array, whose three states
(empty, ready to cast, awaiting rest) are fixed by five agreeing routines in the
original executable, with each spell's level taken from the game's own table.
Only per-level counts leave the reader: never a spell list, a spell id, or a raw
slot byte.

[Download the public APK](https://github.com/huntergdavis/poolrad-macmaps/releases/download/v0.18.0/poolrad-macmaps-0.18.0.apk)
and install over the existing app. **Bring your own ROM, Mac system and game**;
none are included. No game rules, stats, save formats, notebook identities or
handwriting formats change, and nothing is written to guest memory.

Mac II universal, Android 5.0+, ARM64/ARMv7/x86/x86_64, versionCode 84.
Same prototype signing key; source tag `v0.18.0`.

**393 Java tests** and the rebuilt native party-probe suite pass, as does the
public APK asset gate. The native tests exercise every spell id 1..127 in both
states and every invalid level byte.

Verified by playing the original game: memorizing Cure Light Wounds produced
"Awaiting rest: level 1 × 1" while the guest's own window listed exactly that
one pending spell and its allowance line moved from 3 to 2; when the city watch
interrupted the rest, both returned to empty together. **A completed rest was
never observed** — every attempt in that street was interrupted — so the
transition to "ready to cast" rests on the decoder tests rather than live play.
Physical e-ink acceptance of these lines is untested.
