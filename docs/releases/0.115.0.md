# 0.115.0 — One-tap Quick load after reboot

New quick, named, and automatic saves now keep the matching disk contents.
Quick load restores the newest quick save and its disk together, including
after reboot or when no disk is mounted. No separate disk selection is needed.

Disk storage uses one shared compressed base per image and stores only changed
4 KiB blocks with each save. Local 12–64 MiB disks used 4.4–13.1 MiB once
for the base. A unit fixture with two changed blocks used under 20 KiB for
the save's disk sidecar. A save that changes much of a disk can be larger.

Each recovered disk is checked by SHA-256 against the saved fingerprint
before it is installed. A rejected restore puts the previous disk back.
Saves made before this release still need their original exact disk contents.

Verified on a disposable Android emulator: after a new Quick save, a cold
process start with the disk file removed needed one tap on Quick load to
recreate the 12 MiB disk and complete native restore. A separate cold start
with one changed disk byte also completed and restored the saved SHA-256.
The final indexed build repeated the no-disk test successfully. Its later
Quick save had a 121-byte disk sidecar and took about two seconds on the
background worker; its one-time compressed disk base was 3.8 MiB with a
96 KiB shared block index. The full Java suite and native snapshot checks pass.
