# 0.38.0 — Two marks finished, and a way to run the checks

Both items that were half-done are done, and the tooling to verify the next
fourteen releases exists now rather than being reinvented each time.

- **A `W` beside anyone load has slowed.** The game never says so anywhere you
  are looking; you find out by being slow in a fight. It marks whoever is
  behind the rest of the party, and — new in this release — everyone, when the
  whole party is down at the game's own printed floor. A purely relative test
  could never catch that case: when everybody is equally slow, nobody is behind
  anybody.
- **Tap a combatant on the battle overview and that party row lights up** for
  three seconds. On the grid everyone is a circle, so "which of these is
  Tanarakis" had no answer without counting markers against rows. It identifies
  and nothing else: no order is given, no target is chosen, and it fades on its
  own so the pane never acquires a selection you have to remember to clear.
  Tapping a monster lights nothing, because a monster has no row.

**Under the hood.** `tools/verify.sh` now runs the native probe suites, the Java
tests, the APK build and every render check in one command, and
`tools/render-check.sh` compiles and runs a single check on a connected
emulator. Python suites needing a module nobody installed report SKIP instead
of passing silently.

**One finding worth recording.** `tools/PartyPaneRenderCheck.java` has never
been run in this project's recorded history, and on untouched code it failed at
its third check. Eleven of its checks described rules that later releases
deliberately overturned — the strip under the map, the five-second reading
hold, the condition word where the armour class goes, and the refusal to name
an area the companion cannot vouch for. Nine are repaired here; the rest are
tracked as F83 rather than left as a silent hole.

**Verified:** 458 Java tests, five native probe suites, and 14 render checks in
`CombatMapRenderCheck`, including two new ones for the marks above. Synthetic
packets throughout; no captured battle or private character record appears in
any check. Not verified here: e-ink, stylus, or any on-device acceptance —
those remain the owner's own.
