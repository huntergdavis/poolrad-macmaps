# 0.46.0 — What this version of the game actually supports

Research, like 0.43.0 and 0.44.0. The converter has to bring a party from
another platform inside this version's limits, and it cannot adjust to limits
nobody has written down. All of this was read out of the game itself.

## Four classes are named and cannot be played

| Class | Level cap |
| --- | --- |
| Cleric | 6 |
| Fighter | 8 |
| Magic-User | 6 |
| Thief | 9 |
| **Druid** | **none — no experience thresholds at all** |
| **Paladin** | **none** |
| **Ranger** | **none** |
| **Monk** | **none** |

The game knows all eight names and the training table has nothing behind four
of them. A character converted from a version that *has* those classes has
nowhere to go here — so the converter must **say so and refuse**, not pick the
nearest thing. Every combination containing one, such as `Cleric/Ranger`, goes
the same way.

A multi-class character meets its lowest wall first: a Fighter/Magic-User stops
at 6 even though the fighter half could reach 8.

## The lists

**Eighteen classes**, counting from zero, in the game's own order — checked
against the owner's own party, where a class byte of 2 is the fighter, 13 the
"Spellsword" (Fighter/Magic-User) and 14 the dwarf thief (Fighter/Thief).

**Seven races** — Dwarf, Elf, Gnome, Half-Elf, Halfling, Half-Orc, Human —
counting from **one**. That is forced rather than assumed: a real saved
character reads 7, and a list of seven names counted from zero has no 7.

**Spell levels 1 to 3 only**, with 21 memorised-spell slots. Both agree with
what the party reader already assumed.

## Where it came from

The names came out of the game application's own `STRS` resource, read straight
off the game disk using the resource reader built for 0.44.0. The level caps
came from the table the game consults when it decides whether a character may
train. Nothing here is second-hand.

## Not established

**The item catalogue.** Item names live in the game's `ITEM%d.DAX` data files
rather than in any table in the application, so they are a different structure
from the class, race and spell lists, and are now tracked separately. The
converter will need them — an item from another version that does not exist here
is exactly the case it has to refuse.

**Verified:** 516 Java tests including nine new ones, six native probe suites,
25 render checks. The new tests check the lists against the owner's real party,
so a list that is wrong in a way no synthetic case would catch shows up as a
real character turning out to be unplayable.
