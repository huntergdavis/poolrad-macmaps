# 0.60.0 — Save states shrink to a diff

**Save states now store only what changed.** The first save you make becomes a
reference template, kept once, and every save after it stores just its
difference from that template — so a save drops from over a megabyte to tens of
kilobytes.

**Why the first save, not a built-in one:** a machine image depends on your own
ROM, system, and game, which the app never ships, so there is nothing to build
in. The first save you take is the template; it is written once and quietly
kept, and never shows up in your list of saves.

**What this means for you:**

- Quick save and named saves are much smaller and faster to write.
- Everything still round-trips exactly — a save is put back byte-for-byte,
  screen and all.
- Saves you made in the previous version still load.

If the reference template is ever lost, a save that depends on it is refused
rather than restored wrongly — it never guesses.

**Verified:** 600 Java tests, the native build, the APK ABI check, and a live
round-trip on the running machine (first save wrote a 713 KB template and an
8.7 KB diff; both the diff and a wholly-different later save reconstructed
exactly and restored with the screen intact).
