# 0.79.0 — Long-press a party row for the game sheet

F43 adds a long press on each companion party row to open that character's
original-game sheet. Short taps still select the character and show companion
details. Named accessibility actions offer the same game-sheet operation.

The app first selects the exact character through the validated Information
window. It waits for fresh confirmation of that identity, then sends the game's
plain V command. The previously documented Command-E shortcut is disabled
during adventuring; this release corrects that assumption using live evidence.

The native guard requires the authenticated idle exploration/camp input
context and an available, unobscured Information window. It refuses stale or
ambiguous identities, unknown contexts and timeouts. Pause and snapshot restore
cancel queued sheet requests. No character fields are written.

Validation includes 647 Java tests, 27 Android party-view checks, and native
selection/context tests under address and undefined-behavior sanitizers.
The reusable test loader now waits for actual game menus and checks the loaded
party controls without relying on OCR of the Message window's fragile title.

Live on an isolated emulator, long-press opened Lara's sheet from exploration
and Zarram's sheet from camp. An open sheet refused another character request
without changing the displayed character. No physical-tablet retest is claimed.
See docs/PARTY_SELECTION.md for the native evidence and coverage limits.
