# 0.84.0 — Verify disks before restoring snapshots

F97 requires a new PRQS3 snapshot format. Quick, named and automatic snapshots
record the mounted disks' contents and refuse to load if those disks have
changed. Verification happens before the notebook transition and is checked
again at the native restore boundary.

**Older emulator snapshots are unsupported.** PRQS1 and PRQS2 show an explicit
unsupported-format message; there is no compatibility mode or override.
Original-game saves and the shared compression reference remain usable.
Snapshots still contain memory and device state, not disk backups.

Snapshot and reference writes now finish gzip and fsync the open file before
publication. A failed sync preserves existing saves and history. The cached
reference owns its bytes so later caller mutation cannot break existing diffs.

Validation: 673 Java tests, the Android preview codec check, and live matching
restore, post-write mismatch refusal, older-format refusal and native malformed
body refusal. Disposable HFS trials reproduced metadata damage after process
death and loss of a newer game save with orphaned disk blocks after an unsafe
old-format restore. The new guard refused that stale-disk restore path.
Normal-save control results are recorded in docs/DISK_SAFETY.md.

**Hard quits remain unsafe for HFS.** This release guards snapshot consistency;
it does not make abrupt process death transactional. Use normal Mac shutdown
and retain independent disk backups. All destructive audit cases used private
disposable disk copies; no original image was changed. No physical-device
performance or crash-safety guarantee is claimed.
