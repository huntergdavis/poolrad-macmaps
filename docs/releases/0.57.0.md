# 0.57.0 — The header names what you are fighting

**"29 others"** was the least informative thing on the battle overview. It now
reads

> **6 of yours · 12 GOBLIN**

or **8 GOBLIN · 4 ORC** when there is more than one kind, with the counts
falling as the fight thins.

The game gives every combatant a character record and names its monsters there —
ten orcs are ten records all reading `ORC`. So naming them needed no new
reading, only the grouping.

## What it refuses to do

**Only those still standing are counted**, so the number agrees with the squares
beside it.

**It reports no kinds at all rather than some.** An unreadable name, an empty
one, or more kinds than the packet holds all produce nothing, and the header
falls back to "12 others". Naming half the opposition would be worse than naming
none of it.

No monster is named that is not on the field, nothing is said about their
health, and the pane still suggests nothing.

## Two backlog items, one release

F70 (name them) and F71 (count each kind) are one packet change and one line of
text. Splitting a single change across two releases to satisfy a rule would have
been worse work, not better.

**Verified:** 586 Java tests including five new ones, seven native probe suites
including eleven new checks on the grouping, 59 render checks — one of them that
the header stops counting once it can name.
