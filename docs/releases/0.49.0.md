# 0.49.0 — The words the game builds item names out of

Research, like 0.43.0, 0.44.0 and 0.46.0. The converter has to refuse an item
this version cannot represent, and refusing needs a list of what it can.

Read out of the application's own `STRS` resource, in the game's own order:

| Group | Count |
| --- | --- |
| Weapons | 47 |
| Armour materials and qualifiers | 14 |
| Everything else, magic items included | 86 |

**The odd ones are the proof it came from the game.** `Bec De Corbin`,
`Bill-Guisarme`, `Fauchard-Fork`, `Guisarme-Voulge`, `Lucern Hammer`, `Awl
Pike`, `Spetum`, `Bo Stick`. Nobody types that list from memory.

**Names are composed, not stored whole** — which is why a saved game reads
`Banded Mail  Mail` and `Long Sword Sword`: a base word and a modifier run
together. And the game counts things, so the vocabulary has `Arrow` and the save
says `30 Arrows`; a trailing s is not evidence of an unknown word. The tests hold
all of this against the six items a real character on the owner's disk is
actually carrying.

## This is not the equipment reference

The app has shipped one since 0.3.0, covering all 46 weapons in the printed
appendix and all 11 armour rows with damage, weight, class permissions and
armour class. That is what a player reads, and it is unchanged.

This is the vocabulary, magic items included, so the converter can answer *does
this version have that item at all* — and refuse rather than substitute when it
does not.

## Two things that fell out

`PoolRadGen:ITEMS` is a two-byte count of **118** followed by **128 records of
16 bytes** — the items' numbers, not their names. How a record composes a name
is not decoded and is tracked separately.

The same `STRS` run holds the condition names — `Okay`, `Animated`, `tempgone`,
`Running`, `Unconscious`, `Dying`, `Dead`, `Stoned`, `Gone` — in exactly the
order this project decoded them from memory months ago. A free confirmation
nobody asked for.
