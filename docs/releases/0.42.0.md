# 0.42.0 — Saved games can be copied off the disk, and put back

**PoolRad → Saved games** finds the game's own saved games on the guest disk,
copies them into the app's own storage, and restores them.

The disk image is the only copy of those files that exists. Everything else
planned for saved games writes to that image, so this comes first: there is no
honest way to build a save writer before there is a way to undo it.

## What a backup is

Both forks and the Finder type, in one file with a checksum. A Macintosh file is
two forks and a four-letter type, and Android storage has no idea what any of
that is — writing only the data fork would produce a backup the game cannot
open, which is the kind that is discovered to be useless at the moment it is
needed. About 17 KB per save.

Nothing is ever overwritten. A second backup of the same save is a second file,
because the whole point of the first one is that it is still there.

## What it will not do

- **It will not restore while the disk is in the drive.** The emulator caches
  disk blocks; writing underneath it would leave a volume that disagrees with
  itself. Eject the disk first and it says so.
- **It will not restore a damaged backup.** Writing half a saved game over a
  good one is worse than not restoring at all.
- **It will not grow a file.** Bytes go back exactly where they were. A fork
  needing a block the file does not already own is refused — allocating blocks
  means touching the volume bitmap, and getting that wrong on a 64 MB disk with
  your campaign on it is not a bug anyone can apologise for.
- **It will not read a fork that spills into the extents overflow file.** It
  says so rather than returning a short one.

## Verified

499 Java tests including 18 new ones, five native probe suites, 25 render
checks. Two hand-run harnesses against real disks, because a synthetic volume
cannot prove what matters:

- Both of the owner's disks read correctly — `PoolRad Game` with 1 KB
  allocation blocks and a save whose data fork is split across two extents, and
  the boot disk with 512-byte blocks and the Finder's half-megabyte resource
  fork.
- On a **copy** of the real 64 MB disk, every saved game was backed up,
  scrambled, restored — and the whole image came out byte-for-byte identical.

**Not verified here:** on-device acceptance. Nothing in this release has been
exercised through the menu on the tablet; that remains the owner's own.
