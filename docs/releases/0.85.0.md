# 0.85.0 — Resume the latest snapshot on launch

The app now tries the most recently completed quick, named or automatic
snapshot when it starts. The option defaults on; Start normally cancels the
attempt, and Info → Options can turn it off. Background resume and an explicit
Restart Emulator do not repeat the attempt.

A launch restore requires matching mounted disks and an existing notebook
pairing. Missing, corrupt, unsupported or mismatched snapshots continue normal
Mac boot. The app never creates a campaign automatically or silently chooses
an older snapshot after a corrupt newest one.

Fresh-process testing exposed incomplete native device capture. PRQS4 / PRSS3
now includes the configured video, disk, input, sound, serial, VIA and RTC state,
and rebuilds host memory mappings. Machine and ROM headers are checked before
any state is applied. Older emulator snapshots are unsupported; original-game
save files are unaffected.

Validation: 681 Java tests; production device-traversal and packet-state tests
under AddressSanitizer and UndefinedBehaviorSanitizer; fresh-process restore
with correct color video, real guest input and clock advancement; original-game
save/write/readback with all prior file forks unchanged and no added HFS
diagnostics; native model/ROM/truncation refusal; no-save, disabled, missing
notebook, disk-mismatch and cancellation checks. Repeated UI and stopped-disk
audit work now has reusable helpers, and native regressions run before release.
