# 0.30.0 — Your party shows up

The caption in 0.29.0 named it on the first try: `party: heap block rejected
[80000136]`, on the very first character record.

Pool of Radiance keeps each character in a 302-byte block of Macintosh memory.
The app checks that block's header before it will read a single byte out of it,
and one of those checks was simply wrong: it required the block's size to be a
multiple of four. The Mac's actual rule is that it must be *even*. Your Mac
allocates those records at exactly 310 bytes — the record plus its header, no
padding — and the check threw every one of them away.

- **The party pane now fills in**, along with the battle overview, poison and
  helpless marks, which all read the same character records.

The map always worked because the map's blocks are 1024 and 2048 bytes, which
are multiples of four whichever rule you apply. The character record is the one
structure where the two rules disagree, which is why the map has been perfect
next to an empty party pane on every version so far.

Nothing was loosened beyond that: the exact block size is still pinned by the
record's own size and the header's correction field, and the readers are still
read-only.

[Download the public APK](https://github.com/huntergdavis/poolrad-macmaps/releases/download/v0.30.0/poolrad-macmaps-0.30.0.apk)
and install over the existing app. **Bring your own ROM, Mac system and game**;
those are still not included.
