# 0.15.0 — Know how your party is holding up

- Show one quiet condition badge in the party sidebar's existing class-icon
  slot: injured, unconscious, dying, dead, petrified, poisoned, helpless,
  animated, running or temporarily gone. The ordinary class symbol returns as
  soon as no badge is warranted, so a healthy party looks exactly as before.
- Read the condition from the Macintosh character record's own status field and
  its nine-entry name table. Unconscious, Dying and Dead are **never** inferred
  from zero HP, which the original game treats as a separate question.
- Track only the original game's poison and aggregate **Helpless** effects from
  the character's effect chain. Other spell effects are deliberately not named,
  and an unreadable chain reports unavailable rather than "no effects".
- Tap a character for the exact combination in words, alongside the unchanged
  class, health and armor-class lines.

[Download the public APK](https://github.com/huntergdavis/poolrad-macmaps/releases/download/v0.15.0/poolrad-macmaps-0.15.0.apk)
and install over the existing app. **Bring your own ROM, Mac system and game**;
none are included. The personal bundled APK stays local. No game rules, stats,
save formats, notebook identities or handwriting formats change, and nothing is
written to guest memory.

Mac II universal, Android 5.0+, ARM64/ARMv7/x86/x86_64, versionCode 81.
Same prototype signing key; source tag `v0.15.0`. Back up notebooks before
uninstalling or clearing app data; update in place to retain them.

**363 Java tests**, **22 Android software-Canvas checks**, the rebuilt native
party-probe suite and **81 Python helper tests** pass, as do the public APK
asset gate and signature verification. Private RAM captures replay with the six
correct characters, unchanged HP/AC/class, an Okay condition and no tracked
effects; captures the existing application-profile guard already rejected are
still reported unavailable rather than guessed.

Live on the isolated test emulator the six sample characters keep their class
symbols and the details pane reads "Condition: Okay". No character was played
into a rare condition during verification, so the non-empty badges are covered
by the decoder, unit and View suites rather than by gameplay. Physical e-ink and
stylus acceptance of these badges is untested; the user's earlier handwritten
notes acceptance stands separately.
